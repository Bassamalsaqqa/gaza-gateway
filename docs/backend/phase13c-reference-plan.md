## Architectural decisions

1. Add a bounded reference module in the existing monorepo backend. Reuse connection configuration, error envelopes, request correlation, rate limiting, cookie/session stores, canonical RBAC and fail-closed host/CORS configuration. No new framework, identity provider or dependencies without a demonstrated need.
2. Add expand-only PostgreSQL migrations. Existing `fare_products`, quotes/holds/bookings/passengers are already identity dependency tables: inspect and extend references safely rather than recreating them or editing applied migrations. They do not authorize Phase 13D workflows. Reference rows retire rather than delete; booking/pricing/layout snapshots remain untouched.
3. Use per-domain revision-control rows (`fleet`, `network`, `schedules`, `commercial`) and append-only full aggregate revision snapshots. Lock the control row before aggregate writes, increment only on actual changes, atomically persist the new immutable revision and a typed reference audit event. Prevent update/delete/truncate of revision/audit history at the database boundary. Preserve safe integer revision bounds and explicit full-snapshot hashes.
4. The accepted identity audit ledger has closed identity action/target enums and UUID targets. Reference identifiers are often text. Use a separate bounded reference audit ledger with staff FK, fixed action/domain/outcome keys and revision binding; do not weaken identity audit constraints or inject reference data under fabricated identity actions. This is a domain module, not an alternative identity authority.
5. Canonical staff checks require the persisted full, current-MFA staff session, active identity, epoch/expiry/revocation validation and exact permission (`ops.edit` or `commercial.edit`; full catalog read `commercial.view`). Pending/passenger cookies cannot authorize writes. Unsafe cookie requests require unconditional exact Origin and raw `X-CSRF-TOKEN` equality, even with same-origin Fetch Metadata. Source policy comes from the accepted operation registry, never route-caller metadata. Recheck authority within mutation transactions with documented row ordering; do not acquire the last-admin sentinel for reference edits.
6. Keep intact accepted request/response schemas. Commercial commands already carry `expectedRevision`; reject stale values with 409 under the domain lock. Fleet/network/schedule commands do not universally carry that field: preserve their schema, serialize validated patches against the locked current state, and report immutable revisions internally. Do not silently invent required fields, widen closed `SuccessMeta`, or claim client CAS where none is defined. A later explicit conditional-header extension requires Codex review before implementation.
7. Preserve `svc1-<base64url exact UTF-8 schedule ID>-YYYY-MM-DD` identity. Schedule IDs use exact text comparison, no trimming/case changes and a 160 JavaScript UTF-16-unit bound (80 astral characters accepted, 81 rejected), distinct from JSON Schema code-point lengths. Reject invalid Unicode and impossible dates. Weekdays stay 0=Sunday through 6=Saturday.
8. Derive geometry/capacity on the server; never accept caller capacity or inventory claims. Reference layout/equipment changes must not rewrite preserved booked snapshots. Before inventory exists, use explicit reference-only behavior; once 13D is implemented every effect/shrink writer must join the normative service-lock order and commitment checks. No placeholder occupancy calculation may claim full shrink certification now.
9. Public projections contain only the exact safe wire fields. Commercial public reads are active-only; administrative/historical reads retain inactive products. Fleet/network compatibility reads may retain inactive reference rows where their accepted contracts require them; new assignment/discovery must enforce activity. Never promote fixture seats-left, gates, terminal, simulated status or price to operational truth.
10. HTTP repositories are behind an explicit nonproduction opt-in, independent of the default mock path. Once opted in, an API failure fails closed rather than silently substituting local authority. Mock fallback remains available by explicit mode selection until 13G; Studio stays isolated. No public production switch is activated.

## Package-specific fidelity

Fleet: immutable IDs; model 1..120; case-insensitive normalized unique registrations; atomic default/specified layout creation; 1..60 rows; unique uppercase columns; valid aisle; complete non-overlapping cabin zones; unique in-range legroom rows and existing unavailable seats. The source default layout must be copied from `defaultNewAircraftLayout`, not invented. Capacity is grid seats minus distinct structurally unavailable seats. Do not filter inactive historical aircraft out of required compatibility reads.

Network/routes: preserve AMM, CAI, IST, DOH, DXB, JED and RUH; no fabricated LHR route. GZA is the base reference, not an eighth editable destination in the seven-entry source adapter. OpenAPI airport creation is a designed extension of the fixed-code browser repository; keep known-code restrictions and distinguish create conflicts from update/no-op semantics. Route direction derives GZA→destination or destination→GZA; block duration comes from configured reference data, not wall-clock subtraction. Source label bounds (160), timezone bounds (80) and minimum block duration (20) differ from parts of the relational prose/wire minimum (15): package C02 must propose a lossless reconciled storage/command boundary for Codex review before widening or truncating anything.

Schedules: immutable route/direction/ID and retirement; no destructive deletion. Preserve backward-compatible optional structured effects; prose is never parsed as an instruction. Require known network/equipment and valid active assignments for new commands without retroactively erasing historical references. Persist deterministic dated-service identity with an explicit source-revision relation. Origin-local calendar/DST and UTC instants require a documented deterministic policy; departure/arrival wall-clock fields and configured block duration must not be silently equated.

Commercial: preserve all source fare fields including highlight, allowed cabins, bilingual terms and ordering. Preserve fixed essential/economy multiplier anchors, 1..8 valid multipliers without accidental NUMERIC(4,2) rounding, and at least one active fare for each cabin. Source option IDs/labels have broader bounds than portions of relational prose; expand storage losslessly by reviewed new migration. Retiring the default meal is rejected until another active meal becomes default. Use database-level uniqueness plus serialized catalog validation; no display-only guarantee. Reuse `backend-commercial-contracts.mjs` money/receipt projections as test oracles, not a JavaScript server authority.

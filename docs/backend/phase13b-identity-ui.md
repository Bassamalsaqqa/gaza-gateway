# Nonproduction identity UI

> Initial staff enrollment policy is superseded by the [2026-10-13 optional MFA amendment](optional-staff-mfa.md). Historical acceptance results below do not validate this amendment.

Status: implemented locally / Awaiting Independent Review. This is an isolated identity preview, not a production repository cutover or acceptance of Phase 13B.

The existing EN/AR sign-in, registration, recovery, account and staff route entry points select the preview only when `VITE_IDENTITY_UI_MODE=backend`. The default remains mock. An invalid explicit mode selects the blocked server boundary, never mock identity. Set `VITE_IDENTITY_NONPRODUCTION_OPT_IN=true` and `VITE_IDENTITY_API_BASE_URL=https://127.0.0.1:18090/api/v1` in an ignored local development environment. The transport requires a known nonproduction environment and rejects production flags, production hosts, plaintext HTTP, ambiguous URLs and missing opt-in. A production static build cannot enable this preview.

Use the same HTTPS hostname for frontend and API with distinct ports and an exact local CORS origin. Both must have valid browser certificate trust; do not bypass TLS, weaken SameSite cookies or install global owner trust roots. Remote staging evidence remains deferred.

The HTTP passenger repository implements profile/traveler reads and mutations with genuine server receipts. It initializes no browser passenger store, imports no local account, and rejects prototype sign-in, conditional local owner commands and local booking ownership transactions. Default mock repositories remain unchanged. Backend preview overrides Studio's mock passenger selection. The mock admin session coordinator is never initialized in preview mode and exposes no mock permissions. Account/admin layout boundaries omit their mock child outlets, including trip, boarding-pass and backoffice mutation screens.

Passenger screens cover registration, verification/resend, password recovery/reset, real password login, profile, saved travelers, sessions, password change and logout. Staff screens cover independent password/pending MFA, enrollment, one-time recovery display, confirmed identity, sessions, step-up, password/factor changes and permission-gated directory/invitation operations. Permissions and recent verification are rechecked by the server; UI visibility confers no authority. Disallowed actions and invalid sessions show bounded EN/AR messages without raw exceptions or PII.

Five guest/claim methods extend the existing transport to 46 accepted operations. Their static expectation fixture pins the accepted paths, statuses, security and authorization metadata; the generator emits their actual reachable schemas. Guest OTP verification discards the returned grant because booking management is not enabled. Ownership uses a separate authenticated challenge, verified memory-only single-use proof, and an explicit confirmation action. No booking creation, seat inventory or itinerary is synthesized. Receipt mint/management consumers belong to Phase 13D.

Passwords, OTPs, verification/reset tokens and recovery codes are cleared after submission. Setup secrets, recovery-code displays and claim proofs remain in component memory only; they clear at their deadline or when the tab becomes hidden. Recovery display is capped at five minutes. No URL tokens, browser-storage credentials, persisted mutation cache, external QR service, credential console logging or JWT is introduced. Workspace generation checks reject late session refresh results after another refresh/logout/unmount. Profile/traveler forms are scoped to the current server account; staff forms to the current server principal. CSRF rotation protects cross-tab command authority.

Focused package checks: nine new boundary/guest transport tests passed; the two affected client metadata/negative-matrix tests passed with 46 operations. These fetch fixtures test client behavior and are explicitly not server or mail-delivery evidence. TypeScript passed after integration. Final exact-source PHP/PostgreSQL, real HTTPS/browser evidence and independent review are still required. Earlier partial edit checks failed on missing route imports and an incorrect locale helper signature; those defects were corrected before this package's successful typecheck.

The subsequent [final local gate](phase13b-final-local-gate.md) records cumulative PHP/PostgreSQL, all 46 actual-operation response checks and thirteen focused trusted-HTTPS Chromium checks. Those results supplement the package checks above; they do not constitute a single uninterrupted broad green suite, a full viewport/browser matrix or independent acceptance.

This preview does not activate real mail delivery, paid services, owner administrator custody, DNS, deployment, Actions or Phase 13C. Local synthetic proof delivery fixtures cannot prove a remote provider accepted mail.

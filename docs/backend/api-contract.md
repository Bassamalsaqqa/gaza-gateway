# Versioned API and wire contracts

Status: Phase 12 design complete / awaiting independent GitHub review.
Base path: /api/v1. openapi.v1.json defines wire schemas; operation-policies.v1.json pins exact security alternatives and context predicates. 138 operations, 131 paths and fourteen Phase 13A–G tags. API schemas describe planned server behavior; frontend source-backed adapters are development tooling.

## Common protocol

Success JSON: {success: true, data, meta}; meta includes request correlation. ErrorResponse: {success: false, error, meta}; use stable code/message/field errors, never exception traces or PII. Exactly GET /auth/csrf and GET /staff/csrf return raw {csrfToken}. A 204 response has no content body.

Require and validate X-Request-Id, generating an opaque server ID if absent/invalid. Return the same correlation header/meta for successes and errors. All private/auth/checkout JSON uses Cache-Control: no-store. Read pagination/filter bounds from declared parameters; stable server ordering, capped pages and scoped counts. No global query exposes foreign users or inbox PII.

Cookies: gza_session, gza_staff_session and gza_staff_pending. Headers: raw X-CSRF-TOKEN; X-Booking-Token for scoped guest authority; X-Booking-Receipt for minimal receipt; X-Signature denotes the configured native webhook adapter. Exact Origin/CSRF behavior on every route is x-protocol; see auth-rbac.md. Ignore request-supplied roles, principal IDs, permissions and security epochs.

Idempotency-Key on stateful financial/inventory/publication commands is scoped to server actor/realm/operation and canonical command+path hash. Same key/body replays an authorized non-secret receipt, changed body returns 409. Reservation/outcome and domain mutation commit together. Existing no-op mutation receipts preserve changed: false.

Optimistic expectedRevision fields are required for CMS and settings drafts/discards and sealing. Route document slug must match payload.id and payload.kind. Publication sealing compares every canonical document/contact/appearance/archive revision. Unknown/stale revision is 409. Domain source mutations retain their real receipt families; swapping a different successful response is rejected.

## Error behavior

| HTTP | Meaning / stable examples                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------- |
| 400  | Invalid command/protocol, missing immutable release pin                                                                         |
| 401  | Missing/invalid/expired/revoked credentials                                                                                     |
| 403  | Insufficient server permission, foreign owner/action or disallowed Origin                                                       |
| 404  | Unknown scoped resource or release pin; no foreign-resource disclosure                                                          |
| 409  | revision_conflict, idempotency_conflict, capacity_unavailable, blocked_shrink_conflict, last_admin_conflict, ownership_conflict |
| 419  | Missing/mismatched raw realm CSRF header                                                                                        |
| 422  | Invalid field/domain semantics, codec/calendar/count/linkage                                                                    |
| 429  | Persisted rate budget exceeded; Retry-After                                                                                     |
| 503  | Unavailable authority/provider; never pretend mutation succeeded                                                                |

## Domain invariants and adapters

- Exact schedule/service IDs preserve interior whitespace, case and Unicode; the existing codec's 160 UTF-16-unit schedule bound differs from schema code-point lengths. Weekdays are 0=Sunday..6=Saturday. Schedule local HH:mm is an explicit pattern; protocol timestamps are RFC 3339.
- Fleet commands mirror AircraftCreateInput/UpdatePatch and physical LayoutUpdateInput. Capacity is server-derived. Network CreateAirportRequest is a designed Phase 13C extension around the authentic airportName/city/country/timezone/blockMinutes/active type.
- Money uses safe integer USD minor units. Source extraBagPrice 35 becomes 3500 exactly; unsupported currency/fractional precision rejects. Fare/cabin multipliers remain unitless. Public catalog is active-only, admin snapshot includes inactive options.
- Passenger profile email is immutable. Preserve preferences/newsletter, opaque stable traveler IDs, free-text nationality, single names and empty saved DOB. Changed meal preference requires the authoritative active catalog; traveler PATCH merges owner-scoped current context before validating.
- CreateQuoteRequest paxCount is all passengers; optional infantCount defaults zero. Seated count = paxCount - infantCount. Quote -> hold -> booking -> intent must share the live server checkout session. Hold requests must match quote itinerary/cabin/count. No caller price, capacity, paid status or actor identity.
- CreateBookingRequest passenger IDs are request-local. Lap infant linkage points to an adult, with at most one infant per adult and no physical seat. Pre-booking seat selections use datedServiceId/passengerId; post-booking seat management uses persisted leg identity. Check-in is per passenger and leg; infants have nullable seatCode.
- CreateBookingResponse issues a distinct ten-minute receiptGrant once. Ordinary booking detail has no receipt token. Guest management uses its two-step ten-minute OTP and fifteen-minute action-scoped grant; authenticated ownership claim is separate and single-use.
- Appearance accepts six authentic surface families and registered targets/tokens. Legacy cards is quarantined; gza-geometric canonicalizes to pie-factory. Target truth policy precedes family policy. Future AI concepts cannot become Past/Present documentary evidence.
- CMS keys are home, travel, airport.past, airport.present, airport.future, destinations.presentation, destinations.editorial, pages.information. Settings use flat authentic contact fields including socialYouTube, and admin.manage.
- Public contact acknowledgement omits submitter email, notes and drafts. Duplicate submissionId with identical body reuses intake; differing body conflicts. Reply-draft is the sole source-backed reply operation and is never claimed sent.
- Public archive snapshots preserve evidence/rights/publication basis and uncertainty; internal filenames/intake/curator metadata are omitted. Source-provenance enums and all genuine catalog records remain lossless in administrative DTOs.
- Publication reads use exact immutable release pins, hashes and environment. Build receipt -> owner deployment receipt + fixed-origin probe -> step-up/CAS activation; rollback appends a new event to a retained release.
- PaymentEventDto describes a normalized adapter event. The configured provider's native raw signature/merchant/timestamp must be verified first. Late success never reacquires inventory and cancellation waits for verified full refund.

Named development libraries: backend-commercial-contracts.mjs, backend-passenger-contracts.mjs, backend-editorial-contracts.mjs and backend-specimen-catalog.mjs. They exercise real in-memory source receipts; they are not runtime API clients. identity/integrity/publication models consume maintained state and explicitly mark synthetic crypto/provider/probe evidence.

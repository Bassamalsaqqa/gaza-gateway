## Domain and publishing

`src/content/types.ts` owns eight typed documents with explicit English and Arabic text. Ordered arrays own ordering, and stable IDs survive editing. Home hero/search/board remain required and locked. Travel, Past, Present and destination structural identities remain bounded by schema.

`src/content/schema.ts` validates bilingual plain text, identity, schema version, unique IDs, structural sets, visibility, approved media and source references. HTML blobs, executable URLs and arbitrary media paths are rejected. Editorial records do not own operational fields or invent documentary provenance.

Published records remain serializable compiled TypeScript data. Static route heads consume compiled bilingual SEO through `compiledContentHead`; visitor-local drafts cannot participate in prerender metadata. Shared public navigation remains compiled in `src/lib/site-navigation.ts`.

## Local draft and preview

`LocalContentRepository` uses the existing envelope `localStorage["gza.content.draft.v1"] = { schemaVersion: 1, drafts: { ... } }`. Missing or valid empty storage means no drafts, with no writes on read. Corrupt or unsupported envelopes, unavailable storage and invalid requested documents throw typed errors. Raw bytes and unrelated sibling drafts are preserved; no automatic repair/migration occurs.

Saves/discards use detached validated values, serialized writes, canonical rereads and an optimistic stored-draft baseline. Stale edits reject with `draft_conflict`. No-ops produce no writes/notifications. Failed persistence does not partially adopt state or clear the operator's draft. Native storage events refresh other tabs. Studio uses an isolated in-memory repository.

Normal public URLs always use compiled content. Explicit `?contentPreview=1` applies the current browser's draft after hydration; the initial server/client render stays compiled. A failed preview shows compiled content with a localized explanation and leaves storage untouched. Saving a draft does not publish, deploy or send it elsewhere.

Administrative commands require admin/editor authority and record successful meaningful changes through ActivityRepository after content commits. Audit failure warns without claiming rollback; no-ops and failed content commands create no event. Audit summaries contain bounded structural information rather than whole authored documents.

Home and Travel editing is integrated. Airport, destination and informational-page editing is delegated and not yet accepted as complete. See [CMS workflows](CMS_WORKFLOWS.md) for the exact contract and current implementation boundary.

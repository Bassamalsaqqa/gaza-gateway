# Staff access refinement — source review evidence

This source-only package is based on PR #7 at `c6d829e8aa7e687d1f3b7b06019cf9058fa60c6b`. Main and the installed application remain `b3afa9cf08fc746a9ff7e3e9fbee66c38244fb87`. No production package, merge, deployment, provider configuration or live mutation is included.

## Implemented behavior

- Admin sign-in accepts a staff username or normalized staff email through the existing `username` wire field. Passenger accounts cannot authenticate as staff. Ambiguous aliases fail closed, and both valid aliases share the same account/IP login budget. The directory sentinel protects the revalidated match.
- A single sign-in form links to dedicated bilingual recovery, reset and invitation pages. Recovery acknowledgement remains non-enumerating. Staff passwords, Argon2id, CSRF, RBAC, session revocation and enrolled MFA remain unchanged; existing never-enrolled password sign-in is preserved.
- Newly rendered staff invitation and password-reset emails contain action links built from an approved configured origin. Canonical proof tokens use URL fragments, are held in memory and removed from the address bar. Opening a page never consumes a proof. Submission uses existing single-use server operations.
- Missing, malformed, expired and used links have actionable messages. Generated routes and command/client contracts reflect the approved staff identifier boundary. Passenger account behavior and flight offerings are outside this package.
